really need to explain. Please read:

- <https://docs.solidjs.com/solid-start/getting-started#project-files>

### `/migrations/` directory

Has the Kysely migrations. Because of not using the type `any`, each migration
file has to have the `InitialDB` that you can get it from the previous migration
with something like:

```ts
import type { DB as InitialDB } from "./1743126287135_initial.ts";
```

and export the type `DB` from `kysely-codegen` like:

```ts
import type { DB } from "kysely-codegen";
export type { DB };
```

This export will only be valid for the last migration. If you create a new
migration, before generating the new `DB` type, copy and paste the previous one
on the previous last migration and export that, or figure other way around.

All of this just because of `any`. I'm sorry.

### `/better-auth_migrations/` directory

Automatically generated by Better Auth via
`deno run -A
npm:@better-auth/cli@latest generate`.

I suggest you run that command every time you change something in
`/src/auth.ts`. It will create a SQL file with the tables Better Auth will need.

Now you'll need to figure out what did it add or removed in relation with the
last migrations. For now because there's only one migration, I just run the
`diff` command on both migrations.

After that, rewrite that SQL just with the changes you need. If the difference
is that now there's a new column in that table, use `ALTER TABLE` or find a
workaround depending on the BD you are using.

Careful because no information should be lost during this process.

Then create a migration using kysely with `deno task make_migration <name>`.

In there yoou can do something like this (see
`./migrations/1745131434964_better-auth_migrations.ts`):

```ts
const migrationFile = "better-auth_migrations/2025-04-21T01-12-43.027Z.sql";
export async function up(db: Kysely<InitialDB>): Promise<void> {
  await Deno.readTextFile(migrationFile).then((raw) => {
    for (const i of raw.split("\n\n")) {
      sql`${sql.raw(i)}`.execute(db);
    }
  });
}
```

I feel like this is a very error prone method to deal with this migrations.
Accepting suggestions for different ways.

### `/seeds/` directory

Kysely can run these with `deno task --eval "kysely seed:run"`

If you call that twice, the seed is run again.

### `/deps.ts` file

export `node:` dependencies to use on other parts of the code.

### `/generate_nav.ts` file

Generates the file `/src/generated/docs_nav.ts` using the contents from
`/src/routes/docs/` to be used by `/src/components/DocsSidebar.tsx`.

There's the deno task `gen_docs_nav` that is run every time you `deno task dev`
or `deno task build` as a dependency.
